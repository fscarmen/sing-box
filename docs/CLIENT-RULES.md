# 客户端代理规则

“代理规则”页面管理本项目向客户端下发的路由规则。它展示当前服务器生成的基础规则和最终规则，无法读取手机/电脑上的本地覆写、实际启用的配置或同步状态。自定义规则对本项目 sing-box 和 Xray 两套订阅统一生效，节点配置和下载密钥各自独立。

## 从连接历史添加规则

1. 打开 sing-box 的“连接历史”，找到目标域名或目标 IP，点击“设置规则”。
2. 默认精确匹配这个目标。需要覆盖子域名时选择“域名及子域名”，自行填写希望覆盖的域名，不会自动扩大为主域名。
3. 选择“代理”“直连”或“拒绝”，保存并发布。
4. 在客户端更新并启用对应的完整配置。已连接的请求可能需要重新连接才使用新策略。

新建规则放在列表最前；同类型同目标已有规则时更新并提升其优先级。历史中的“客户端规则”列是按**当前已发布规则**推算的命中，不是该条历史连接当时采用的客户端策略，也不证明客户端已经更新。

VPS 只能看到经过自己的请求。设为直连后，流量在手机/电脑直接访问目标，通常不会再出现在 VPS 的连接历史中。Xray 原生统计不提供目标域名历史，因此无法从 Xray 的流量记录凭空生成目标；仍可在规则页手动添加。

## 规则与优先级

支持精确域名、域名及子域名、域名关键词、IPv4/IPv6 CIDR。纯 IP 自动补 `/32` 或 `/128`，域名标准化为小写/IDNA。目标不支持 URL、路径、通配符或内嵌端口。

规则按列表从上到下匹配，可以编辑、禁用、删除、上移和下移。启用的自定义规则优先于基础目标规则；sing-box 需要的前置 sniff/DNS 动作保留。“未命中时的策略”默认保留各格式的基础规则；选择默认代理/直连/拒绝时只替换最终兜底，基础规则中具体域名/IP 的匹配仍然保留。

“代理”在 Clash 完整配置里指向自动加入的“面板代理”选择组，可在客户端选择本订阅的节点；sing-box 使用已有代理 final/selector，或首个可用代理出站。“直连”指客户端本地直连，不是 VPS 上的 direct 出口。这里管理的是客户端路由，不修改 VPS 入站、出站或防火墙。

## 各客户端如何更新

| 客户端 | 使用的链接 | 更新方式 |
| --- | --- | --- |
| Clash Meta / Mihomo | `auto` 或 `clash2` 完整配置 | 更新订阅并重新加载；使用规则模式。只更新 proxy-provider 节点列表不会更新规则 |
| sing-box | `sing-box` 完整 JSON | 更新并重新加载完整配置。路由片段不能作为完整配置直接运行 |
| Shadowrocket | 原节点订阅 + `shadowrocket.conf` | 节点仍更新原链接；规则首次在“配置”中添加并启用远程配置，后续更新远程配置 |
| v2rayN | 原节点订阅 + `rules-v2rayn.json` | 路由 JSON 单独导入；节点订阅更新不会覆盖客户端路由 |
| Throne / 其他 URI 订阅 | 原节点订阅 | URI 不携带路由；使用客户端自己的路由功能，或其支持的完整 sing-box 配置 |

在“代理规则 → 当前下发规则与预览”选择内核及格式，复制对应链接。Shadowrocket 选择 **Shadowrocket 远程配置**，到手机“配置”页面添加 URL，下载后启用；这会替换当前启用的规则配置，原来的本地分流规则不会自动合并。生成文件包含 `update-url`，后续更新此远程配置即可获取面板修改。`PROXY` 使用 Shadowrocket 当前选中的节点。该文件没有手机已有的基础规则，“保留各客户端基础规则”时默认 `FINAL,PROXY`；可自行添加所需直连规则。各版本具体按钮/自动更新行为以客户端为准，本项目不宣称单次节点订阅更新能同时更新 Shadowrocket 规则。

客户端全局模式、本地覆写、缓存或选错配置可能使新规则未生效。这里不主动控制客户端，也不记录“设备已同步”状态。公开规则集的远程内容不会由面板下载展开，预览显示其引用。

## 保存、订阅与恢复

保存时先校验规则及两种内核当前的客户端配置，再原子替换同一份策略；版本冲突拒绝覆盖，需刷新后重试。保存不重启代理核心，不改变订阅 URL。后续重新生成、升级、恢复核心配置和更新面板仍使用这份规则。删除/禁用全部自定义规则并恢复默认“保留”时，原始完整配置字节保持不变。

规则位于 `/var/lib/sb-subscriptions/client-rules.json`，root:sb-dashboard 0640；修改前备份位于 `/var/lib/sb-manager/client-rule-backups/`，仅 root 可读。服务端运行配置与节点备份不覆盖统一客户端规则。需要手工恢复时，root 将所需备份复制回规则文件并设为 root:sb-dashboard 0640，无需重启核心；先确认 JSON 内容有效，再在客户端更新配置。

管理只向主管理员开放，写入需要登录、Origin/CSRF 和本地任务锁；额外监控账户无权读取/修改。公开下载继续需要独立订阅 token，不能下载规则存储、备份、节点服务配置或任意路径。规则页的配置链接同样包含下载密钥，请私密保存。

## 开发验证

`PyYAML 6.0.3` 用于解析 YAML 路由，并只替换路由相关的 YAML 语法节点，保留节点密码的原始标量写法，避免 `001234`、`on/off` 等被当作数字/布尔值改写。

可选执行 `python3 scripts/fetch-test-mihomo.py` 获取 SHA256 校验后的官方 Mihomo 1.19.33，仅用于测试，不安装服务。设置 `MIHOMO_TEST_BINARY`、`SINGBOX_TEST_BINARY` 可运行真实核心配置/流量验证。隔离容器端到端脚本为 `scripts/smoke-test-client-rules.py`，仅允许明确标记的可丢弃 Docker 环境，不能在生产 VPS 运行。

格式依据：[Mihomo 规则](https://wiki.metacubex.one/en/config/rules/)、[sing-box 路由](https://sing-box.sagernet.org/configuration/route/rule/)、[v2rayN 自定义路由](https://github.com/2dust/v2rayN/wiki/Description-of-custom-routing-rules)。Shadowrocket 远程配置未在真实 iOS App 中测试。
